---
title: How duplicate matching works
description: The details behind Duplicates, for video, images and audio.
---

The [Duplicates](/docs/features/duplicates) page keeps things simple. This page explains what actually happens, which helps when you want to tune the settings.

## Two steps: prepare, then compare

Finding duplicates is split in two on purpose.

1. **Preparing** (the **Extract** or **Find duplicates** button) runs in the background and reads extra information out of the files that scanning does not collect. The results are stored with each file.
2. **Comparing** happens in your browser, over the information that is already loaded. Parallax does not store a list of results, and the server does no comparing at all.

Because comparing is just a calculation over data you already have, switching a chip on or off updates the groups instantly, without a new job. The calculation runs in a background thread of the page, so the page never freezes.

## Cheap checks first

Some criteria use details already known from scanning: size, duration, resolution, content date, orientation, bitrate and file name. These cost nothing.

Before preparing anything, Parallax applies the cheap criteria you have switched on, in that order, and throws away every file that cannot end up in a group of two or more. Only the files that survive are read in depth. So a library of thousands of files with Exact size and Duration switched on may need only a handful of files prepared. The same logic is used again in the browser when it forms groups, so both agree.

Preparing is also incremental. A file that already has what the current settings need is skipped. Changing the visual match to use more frames, for example, prepares only the files that were done with fewer.

## The criteria in detail

**Filename.** Compares names by their overlapping pairs of letters ("bigrams") and gives a similarity from 0 to 100 percent. The threshold slider sets how high that has to be.

**Byte hash.** A fingerprint of the entire contents of the file. Two files with the same hash are identical byte for byte, regardless of name or folder. It is the only exact check, and it reads the whole file, so it is the slowest one to prepare.

**Visual.** For each video, Parallax pulls out frames at a small size (256 pixels) and reduces each to a 64 bit perceptual hash, a compact description of what the picture looks like that does not change much when the file is re-encoded or resized. Two hashes are compared by counting the bits that differ, between 0 and 64. Similarity is shown as `100 - (differing bits ÷ 64 × 100)`. The default of 84% therefore allows up to 10 bits of difference.

- **First frame only** is quick but can be fooled by videos that open the same way, such as the same studio logo.
- **All frames** takes the number of frames you choose, from 4 to 64 (16 by default), spread through the video. Two videos match when their frames line up, which is far more reliable and takes proportionally longer.

**Audio fingerprint.** The sound is turned into a compact fingerprint using Chromaprint, the same technology used to recognise songs. Fingerprints are compared by how many of their bits agree, as a percentage. It matches the same soundtrack even when the video differs or the audio was re-encoded.

## Images and audio

- **Images** use the same 64 bit perceptual hash on the single picture, and the grouping is done on the server, not in the browser. The hash is stored when an image is scanned, and the Find Duplicates button fills in any that are missing.
- **Audio** has four criteria: exact size, duration, content date and the audio fingerprint. Preparing computes the fingerprints, and grouping happens in the browser exactly as for video.

## Which copy is kept

The suggested copy comes from the information Parallax already has about each file. Nothing extra is read from the files. For video and audio it is worked out in the browser together with the grouping. For images the groups come from the server, and the suggestion is worked out in the browser from the images in each group.

Copies are compared one step at a time. At each step, Parallax finds the best copy and drops every copy that is clearly worse. Copies within the step's tolerance of the best one count as tied and go on to the next step. A difference smaller than the tolerance never decides on its own.

**Video**

1. **Duration.** The longer copy wins. Differences under a second or 0.5% are ignored.
2. **Resolution.** More pixels win. Within 2% counts as the same.
3. **Quality per bit.** Video bitrate multiplied by how efficient the codec is, relative to H.264. For example AV1 is 1.9, HEVC 1.6, VP9 1.4, H.264 1.0, VP8 0.9 and MPEG-4 0.6; older codecs such as MPEG-2 are lower still. Within 3% counts as a tie. If either file has no video bitrate, both use their whole-file average (size ÷ duration) so the two sides stay comparable.
4. **Frame rate.** The higher one wins. Within 2% counts as the same.
5. **File size.** The bigger file, as a last resort.

**Audio**

1. Duration, as for video.
2. Lossless over lossy (FLAC, ALAC, WavPack, APE, TTA and PCM count as lossless).
3. Bitrate multiplied by codec efficiency (Opus 1.7, AAC 1.3, Vorbis 1.2, E-AC-3 1.1, MP3 1.0, WMA 0.9, AC-3 0.8, MP2 0.7). Within 3% counts as a tie.
4. Sample rate (within 2% counts as the same), then number of channels.
5. File size.

**Images**

1. Pixel count (within 2% is a tie).
2. Lossless format (PNG, BMP, TIFF) over lossy.
3. Bytes per pixel, weighted by format efficiency (AVIF 1.9, HEIC 1.6, WebP 1.3, others 1.0). Within 3% counts as a tie.
4. File size.

Photo details such as the date, camera and location are not compared. Parallax picks the better picture, not the one with more labels.

### Perfect copies

Copies that tie on every step, such as exact duplicates in two folders, are all equally good, so Parallax keeps the one with the lowest internal id, which is the one it saw first. The result never depends on the order the group was built in.

### Your own ticks

The ticks you see are Parallax's suggestions with your own choices laid over the top. Every time you tick or untick a copy, Parallax remembers that choice for that copy. When the groups change, because you toggled a chip, the files changed or a different copy became the suggested keeper, your choices still apply and only the copies you never touched follow the new suggestions. A copy you unticked stays unticked even if it leaves every group and comes back later.

Your choices are kept while you stay on the page. Picking a different library, or leaving the page, forgets them. Using **Clear** after a delete also counts as your choice, so those copies stay unticked.
